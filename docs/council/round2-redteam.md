## 1. Red-Team Attack on Round 1 Proposals

All three Round 1 proposals converged on the same high-level architecture: **keep the MV3 browser extension for zero-frame DOM safe-reveal, move network/domain authority into `Toolize.Service` via loopback DNS + Windows Filtering Platform (WFP), and add an on-device screen guard for native desktop apps.**

Now we attack the specific mechanisms proposed by **Systems (`round1-systems.md`)** and **Architect (`round1-architect.md`)** from two perspectives:
- **The Determined Teen ("The Tinkerer"):** Standard User daily account (parent holds Admin and the USB key), high technical curiosity, hours of free time, willing to use portable tools, game launchers, proxies, and Win32 quirks.
- **The Struggling Adult at 2 a.m. ("The Impulse Adversary"):** Often still holds Local Admin or knows where the recovery/key lives, wants immediate low-friction relief, and will exploit any race window, false-positive fatigue, or unguarded app path.

*(Difficulty scale: **1** = Trivial (<1 min, UI clicks) · **2** = Easy (settings, flags, portable downloads) · **3** = Moderate (CLI, registry, scripting, Win32 tools) · **4** = Advanced (network tunnels, boot/recovery, custom binaries) · **5** = Expert (kernel/hardware).*

### 1.1 Loopback DNS (`127.0.0.1` / `::1`) + Persistent WFP Rules

*Proposed by Systems (§B) and Architect (§C.2): Service runs a loopback DNS proxy on TCP/UDP 53, sets adapter DNS and NRPT rules, and uses persistent WFP ALE filters (`FWPM_LAYER_ALE_AUTH_CONNECT_V4/V6`) to block external port 53/853 and known public DoH/VPN/Tor endpoints.*

- **How to defeat it:**
  1. **Direct-to-IP / Shared-CDN Host Header Routing (Diff: 2):** Because WFP ALE filters see only IP addresses and ports—not HTTP paths or encrypted TLS hostnames—the user resolves a blocked domain on a phone or via a web-based DNS lookup tool (e.g., `dns.google` JSON API over HTTPS port 443, which is a normal web page, not RFC 8484 DoH), puts the IP or a Cloudflare/Fastly edge address into `curl --resolve` or an unmanaged app, or uses a web proxy / translator (`*.translate.goog`, `web.archive.org`, CroxyProxy) hosted on an allowed CDN IP.
  2. **Encrypted Client Hello (ECH) + Unlisted DoH/SOCKS5 over TCP 443 (Diff: 3):** A teen spins up a free Cloudflare Worker, AWS free-tier proxy, or obscure DoH resolver on TCP 443. WFP sees standard outbound HTTPS (`TCP 443`) to a major cloud ASN that cannot be blanket-blocked without breaking the internet.
  3. **WSL2 / Hyper-V Virtual Switch / USB Tethering Race (Diff: 3):** When plugging in a phone via USB RNDIS tethering or spinning up a WSL2 NAT adapter, Windows creates a new interface and assigns DHCP DNS servers. During the reconciliation gap before `Toolize.Service` rewrites the new adapter's DNS server address—or if `wsl.exe` uses its own virtual switch bypassing host loopback—queries escape unless WFP explicitly drops all non-loopback port 53/853 traffic on *every* interface weight (`FWP_CONDITION_FLAGS` without interface exclusions).
- **Residual Counter:**
  - Never rely on adapter DNS reconfiguration alone: install a **boot-time + persistent WFP sublayer** that unconditionally blocks `TCP/UDP 53` and `TCP/UDP 853` to any non-loopback IPv4/IPv6 destination for all processes except `Toolize.Service.exe` (matching `FWPM_CONDITION_ALE_APP_ID`).
  - Block known DoH/VPN/proxy endpoints using curated IP/domain lists (HaGeZi DoH/VPN/Bypass), and rely on the **browser extension + screen guard** to catch whatever slips through over shared-CDN HTTPS or ECH.

### 1.2 Browser & OS DoH Policies (`DnsOverHttpsMode`, `BuiltInDnsClientEnabled`, Windows DoH)

*Proposed by Systems (§B): Write `DnsOverHttpsMode="off"` and `BuiltInDnsClientEnabled=0` to HKLM for Chrome, Edge, and Brave, and disable Windows 11 encrypted DNS.*

- **How to defeat it:**
  1. **Unmanaged Chromium Forks & Gecko Portable Builds (Diff: 1–2):** A teen downloads a portable ZIP of Opera GX, Vivaldi,Thorium, Ungoogled Chromium, or Floorp, renames the executable to `discord_updater.exe` (defeating `WatchdogService.cs:42`), and enables built-in DoH or Opera's built-in proxy. None of these read `HKLM\SOFTWARE\Policies\{Google\Chrome, Microsoft\Edge, BraveSoftware\Brave}`.
  2. **Per-User Policy Precedence / Profile Flags on Unenrolled PCs (Diff: 3):** On a Windows Home machine that is not Active Directory or MDM domain-joined, Chrome restricts certain enterprise policies or allows command-line flags (`--dns-over-https-mode=secure`) if launched via a custom shortcut unless verified active in `chrome://policy`.
  3. **App-Internal DoH (Diff: 2):** Apps that bundle `c-ares`, `reqwest`, or custom Chromium networking (e.g., certain Electron apps or torrent/chat clients) perform HTTPS POST/GET to DoH endpoints directly over port 443, ignoring Windows `netsh dnsclient` settings.
- **Residual Counter:**
  - Combine `DnsOverHttpsMode="off"` in HKLM with WFP blocking of known public DoH resolver IPs (`1.1.1.1`, `1.0.0.1`, `8.8.8.8`, `8.8.4.4`, `9.9.9.9`, `208.67.222.222`, NextDNS/AdGuard IPs) on **TCP/UDP 443 and 853**, while allowing plain UDP/TCP 53 *only* from `Toolize.Service.exe`.
  - Detect unmanaged browsers by **loaded engine DLLs** (`chrome_elf.dll`, `mozglue.dll`, `xul.dll`) and cover/close them regardless of `.exe` filename.

### 1.3 Service-Owned Signed Blocklist Bundles & Delta Updates

*Proposed by Systems (§B): Scheduled maintainer build publishes RSA/Ed25519-signed OISD NSFW snapshots and deltas; `Toolize.Service` verifies signatures, enforces an 80% count floor / 5% removal cap, and syncs deltas to the extension over Native Messaging.*

- **How to defeat it:**
  1. **Starving the Updater / Replay Freeze (Diff: 2 for Admin, 3 via router/hosts):** An attacker blocks `github.com` / `objects.githubusercontent.com` on their home router or firewall so `Toolize.Service` never receives new domains or newly discovered proxy mirrors, freezing the list at install time while keeping the signature valid until expiry.
  2. **MV3 Dynamic Rule Quota Exhaustion (Diff: 3):** Systems proposes syncing public list deltas from the service into the extension's `declarativeNetRequest.updateDynamicRules`. In Chromium MV3, `MAX_NUMBER_OF_DYNAMIC_RULES` is capped (30,000 rules, or 5,000 regex/safe rules), and in [`extension/src/background/blocklist.ts:101-128`](file:///e:/GithubProjects/Toolize/extension/src/background/blocklist.ts#L101-L128), `added` domains are stuffed into a single dynamic rule (`ADDED_ID = 2`) alongside `learnedSites` (`LEARNED_BASE_ID + i`). If a delta grows large across months without a static CRX release, or if a user triggers thousands of learned sites to hit Chrome's dynamic rule memory/count limit, `updateDynamicRules` throws and the entire dynamic sync fails!
- **Residual Counter:**
  - Once `Toolize.Service` enforces the full 487k+ domain trie in the local loopback DNS resolver, **stop stuffing 50k+ daily OISD diffs into Chrome's fragile MV3 dynamic rule storage**—let the service's loopback DNS block the 487k+ domain list system-wide, and reserve the extension's MV3 dynamic rules strictly for sub-path redirects, SafeSearch, and `learnedSites` (capped with LRU eviction).
  - Include a `manifest.expiresAt` timestamp in the signed bundle and surface a visible "Blocklist stale (>14 days)" warning in `doctor` and the GUI.

### 1.4 Screen Guard via DDA or WGC + Region/Window Covers

*Proposed by Architect (§A.1–A.9) and Systems (§A): Architect proposes change-driven Desktop Duplication API (DDA) → 16×16 colour/gradient "natural image" gate → region proposals → Windows ML (`safety-v3` + NSFWJS) → temporal window → `WDA_EXCLUDEFROMCAPTURE` covers.*

- **How to defeat it:**
  1. **Spoofing the 16×16 "Natural Image" Pre-Gate via Dithering / Colour Quantization (Diff: 3 — Teen / Tool Builder):** Architect (§A.3) proposes skipping inference on any 16×16 block with `≤128` unique colours so UI chrome isn't classified. A 16×16 pixel block has only **256 pixels total**! Even many genuine JPEG photos, smooth skin close-ups (due to 8×8 JPEG chroma subsampling and quantization), manga/doujinshi line art, and GIFs/memes have **fewer than 128 unique RGB values inside a 16×16 block**. Worse, applying a trivial 64-colour or 128-colour posterize/dither filter (or viewing 8-bit GIFs / flat-shaded anime / manga) drops unique colours per 16×16 block well below 128—causing the Gate to classify explicit images and hentai as "UI text/chrome" and **never send them to the ML model at all**!
  2. **Defeating the 64-bit Perceptual Hash Cache (Diff: 3):** Architect (§A.3, §A.8) caches verdicts by a 64-bit pHash of the 224px crop and matches moving tracks by `IoU >= 0.7` and pHash. If a video player or image carousel starts with 3 clean frames (e.g., a solid or mild intro that shares a coarse low-frequency pHash structure, or an image inside a large static frame border where 85% of the crop is unchanged UI padding), pHash collisions or border padding keep the region marked `clean`.
  3. **Strobing / Sub-Window Seeking in Video (Diff: 2):** At 2a.m., an adult scrubbing a video in VLC or Discord rapid-seeks (`Right Arrow` every 400 ms). Because Architect's temporal rule (§A.8) requires *2 flagged frames of the last 3* once a region is shown (unless `safety > 0.97` AND NSFWJS flags), rapid seeking or viewing non-hardcore immodesty (`0.50 < safety < 0.96`) resets or slips between samples.
  4. **Window-Band / Z-Order Escape Above Normal Topmost Overlays (Diff: 2–3):** An unsigned process (even running as `SYSTEM`) creating a window with `WS_EX_TOPMOST` lives in the standard `ZBID_DESKTOP` band. Windows 11 places Start Menu, Task View (`Win+Tab`), Snap Assist thumbnails, Xbox Game Bar (`Win+G`, which has a community browser widget!), and `UIAccess`-signed accessibility tools in higher z-order bands (`ZBID_IMMERSIVE_MOGO`, `ZBID_UIACCESS`), rendering **on top of** Toolize's cover.
  5. **Hybrid-GPU Adapter Mismatch (`DXGI_ERROR_UNSUPPORTED`) (Diff: 2):** On NVIDIA Optimus / AMD SmartShift laptops, plugging into an external HDMI/USB-C port connected to the dGPU (or toggling NVIDIA Control Panel "Display Mode" to dGPU-only) moves the desktop or monitor off the iGPU. If DDA isn't dynamically re-enumerating every `IDXGIAdapter` and `IDXGIOutput` on `WM_DISPLAYCHANGE`, capture silently drops.
- **Residual Counter:**
  - **Fix the Gate:** Never require `>128` unique colours in a 256-pixel (`16×16`) block! That threshold is mathematically broken for skin tones, JPEG 4:2:0 blocks, and anime/manga. Instead, gate on `64×64` tiles using edge-density + entropy, and **always pass skin-tone hues and mid-tone gradients** even when colour count is low.
  - **Escalate to Window Cover on Repeated Seeks/Flashes:** If a window produces >2 doubtful/flagged transitions within 15 seconds, lock the cover on the **entire window client rect** for 10 seconds rather than playing whack-a-mole with moving region boxes.

### 1.5 `SYSTEM`-Token Agent (`Toolize.Guard`) in the User Session

*Proposed by Architect (§A.10): `Toolize.Service` duplicates its `SYSTEM` token, sets `TokenSessionId`, and spawns `Toolize.Guard` on `winsta0\default` with a `SYSTEM`/Admin-only DACL, plus a Low-IL `Toolize.Infer` child process sharing memory.*

- **How to defeat it:**
  1. **Virtual Desktops (`Ctrl+Win+D` / `Ctrl+Win+Right`) (Diff: 1):** A user presses `Ctrl+Win+D` to create Desktop 2. While DDA captures the physical monitor scanout regardless of virtual desktop, `Toolize.Guard`'s overlay `HWND` created on Desktop 1 will **not** appear on Desktop 2 unless the overlay window is explicitly marked as pinned across all virtual desktops or moved via `IVirtualDesktopManager` / cloaking APIs! Meanwhile, DDA sees the explicit content on Desktop 2, `Toolize.Guard` draws its cover on Desktop 1 (invisible to the user), and the user views Desktop 2 completely uncovered!
  2. **Starving `Toolize.Infer` or Flooding the Token Bucket (Diff: 2):** Architect (§A.6, §A.10) runs `Toolize.Infer` at **Below-Normal CPU priority** with a token bucket of **15 regions/s on iGPU** (and for Adult presets, when over budget, it *does not cover* unclassified regions—it only "classifies largest regions first"). A teen opens a wallpaper grid or script with 25 small rapidly animating GIFs on one side of the screen (consuming the 15 regions/s token bucket or starving the below-normal worker with a GPU benchmark/game), leaving a medium-sized Discord/Telegram video uncovered!
  3. **Shatter / Window Station / Graphics Driver Reset (`Win+Ctrl+Shift+B`) (Diff: 2):** Pressing `Win+Ctrl+Shift+B` resets the Windows graphics driver (`DXGI_ERROR_DEVICE_REMOVED` / `DXGI_ERROR_ACCESS_LOST`). If `Toolize.Guard` takes >2 seconds to recreate its D3D11 device, Windows ML session, and warm its ONNX buckets, the user can press `Win+Ctrl+Shift+B` repeatedly to keep the guard perpetually restarting.
- **Residual Counter:**
  - **Virtual Desktop Pinning:** Make overlay `HWND`s top-level tool windows that track the active desktop (or immediately move to the foreground window's desktop on `EVENT_SYSTEM_FOREGROUND`), and verify via a canary pixel or DWM cloaking check (`DWMWA_CLOAKED`) that the overlay is actually uncloaked on the active virtual desktop.
  - **Run `Toolize.Guard` and `Toolize.Infer` at `NORMAL_PRIORITY_CLASS`** (not Below-Normal) with GPU priority `DXGI_OFFER_RESOURCE_PRIORITY_HIGH`, and when the token bucket saturates for >1.5s, fall back to whole-window classification rather than leaving smaller regions uninspected.

### 1.6 Cross-Checks Between Extension and Screen Guard

*Proposed by Architect (§C.3): Cover a browser window immediately if its heartbeat is missing; cover if `GetWindowDisplayAffinity != WDA_NONE`; cover if WGC shows content that DDA missed (`WCA_EXCLUDED_FROM_DDA`).*

- **How to defeat it:**
  1. **Direct Named-Pipe Heartbeat Spoofing (Diff: 3 — Critical Gap in Current Code!):** Look at [`companion/Toolize.Service/PipeServer.cs:28-30`](file:///e:/GithubProjects/Toolize/companion/Toolize.Service/PipeServer.cs#L28-L30) and [`companion/Toolize.Service/RequestHandler.cs:197-211`](file:///e:/GithubProjects/Toolize/companion/Toolize.Service/RequestHandler.cs#L197-L211). Although [`companion/Toolize.NativeHost/Program.cs:190-198`](file:///e:/GithubProjects/Toolize/companion/Toolize.NativeHost/Program.cs#L190-L198) stamps `extensionId` when Chrome talks to `Toolize.NativeHost.exe`, **`PipeServer` allows any interactive process to connect directly to `\\.\pipe\toolize` and send `extension-heartbeat` with `"browser": "chrome"` and `"extensionId": "mckophjbolaofjkhebkcelhnmjofeajf"`!** A 5-line PowerShell loop spoofs a healthy Chrome heartbeat forever, tricking both `WatchdogService` and Architect's cross-check into believing Chrome is protected (and therefore keeping the Screen Guard in low-rate "backstop" mode)!
  2. **Per-Browser vs. Per-Window Blindness (Diff: 1):** [`companion/Toolize.Service/Services.cs:111-120`](file:///e:/GithubProjects/Toolize/companion/Toolize.Service/Services.cs#L111-L120) tracks heartbeats by **browser family** (`"chrome"`, `"edge"`, `"brave"`), not by PID or window handle (`HWND`). If a user has one normal Chrome window open (sending valid heartbeats) and launches a second Chrome instance with a separate `--user-data-dir` (or a custom Chromium wrapper / PWA window where the extension isn't active), the service thinks `"chrome"` is connected and leaves the second window uncovered!
  3. **Legitimate Apps Setting `WDA_EXCLUDEFROMCAPTURE` / `WDA_MONITOR` (Diff: 1 — Usability DoS):** Password managers (1Password, Bitwarden, KeePassXC), banking protectors, Zoom/Teams screen-share HUDs, and DRM players routinely set `SetWindowDisplayAffinity(WDA_MONITOR)` or `WDA_EXCLUDEFROMCAPTURE` to prevent spyware from screenshotting passwords. Architect's rule (§C.3: *"Cover unless the publisher is allowlisted (allowlisting needs the key)"*) will **brick the user's password manager and Zoom controls with an opaque cover** until they go get their physical USB key!
- **Residual Counter:**
  - **Authenticate the Native Host on the Pipe:** In `PipeServer.cs`, inspect the client process PID (`GetNamedPipeClientProcessId`), verify its executable path is `{app}\Toolize.NativeHost.exe`, and verify its parent process is a running browser instance—rejecting any `extension-hello` or `extension-heartbeat` sent by PowerShell or other user processes.
  - **Ship a Built-In Signed Publisher Allowlist for `WDA_EXCLUDEFROMCAPTURE`:** Pre-allowlist Authenticode-signed password managers (AgileBits/1Password, Bitwarden, Dominik Reichl/KeePass, Dashlane) and conferencing overlays (Zoom, Microsoft Teams, Webex) so users aren't locked out of their passwords on day one.

### 1.7 Modesty Taxonomy Presets (6-Level Multi-Label Head)

*Proposed by Architect (§B.1–B.2): Train a 6-level multi-label head (`Explicit`, `Nudity`, `Underwear/swim`, `Revealing`, `Suggestive`, `Romance`) using weak supervision (CLIP RN50 text prompts + NudeNet 640m boxes + NSFWJS scores) and screen composites.*

- **How to defeat it (or watch it fail in the wild):**
  1. **Prompt-Label Noise on `Suggestive` (Level 2s) and `Romance` (Level 1) (Diff: N/A — Model Failure):** Zero-shot CLIP RN50 text prompts (`"a suggestive pose"`, `"people kissing"`, `"revealing outfit"`) have notorious false-positive spikes on ordinary stock photos, sports (wrestling, hugging after a goal, gymnastics), perfume ads, and close-up faces eating or talking into a microphone. Training an MLP head on noisy CLIP text-prompt pseudo-labels without human inspection of positive samples will either miss real movie/music-video romance or blur every drama thumbnail, sports celebration, and wedding photo on the user's screen.
  2. **Cropped / Stylized Anime & Manga Bypass (Diff: 2):** As documented in `CLAUDE.md` (`tools/safety-model/anime-gap.md`), NudeNet was trained primarily on photorealistic images and misses stylized 2D anatomy, while CLIP RN50 embeddings compress 2D black-and-white manga line art poorly. Weak supervision relying on NudeNet boxes + CLIP text prompts for Levels 2–4 will under-detect monochrome manga/doujinshi panels in Discord or local `.cbz` readers while over-blurring safe colourful anime games (Genshin Impact, Honkai, Persona).
- **Residual Counter:**
  - Do **not** replace the battle-tested `safety-v3` binary decision rule with an unverified 6-head weak-supervision model all at once. Keep `safety-v3` + NSFWJS as the hard floor for Levels 3–5, and ship `Revealing`/`Suggestive`/`Romance` as **auxiliary heads that are measured independently in shadow mode (G0)** before they are ever allowed to trigger a screen cover.

## 2. Usability, False-Positive Fatigue & Trust

Security mechanisms that annoy or humiliate the user have a **0% survival rate**: a frustrated adult will grab their recovery code and uninstall; an exhausted parent tired of being called into the teenager's room every 20 minutes with the USB key to unblock homework or a game will turn enforcement off.

### 2.1 Five Places Where the Round 1 Designs Will Cause Uninstalls

1. **The "Cover-New" Grey Strobe (`round1-architect.md` §A.7, G5):**
   - Architect proposes a `cover-new` mode for Kids/Strict presets that places a solid grey cover over **every newly detected photo-like region on the desktop for 33–50 ms** until classified clean.
   - **Why users will hate it:** In a desktop OS, switching tabs in Figma/Photoshop, scrolling a PDF textbook, opening File Explorer in thumbnail view, or flipping slides in PowerPoint creates dozens of "new photo-like regions" per second. Turning the entire desktop into a strobing grey checkerboard on every scroll or alt-tab is visually nauseating and triggers photosensitivity/eye strain. **Zero-frame safe-reveal works in the browser because CSS blurs smoothly inside the layout before paint; on the desktop, `cover-new` must never be on by default.**
2. **Covering Games, Anime & Ad Banners During Normal Use:**
   - As `CLAUDE.md` notes, dataset drawn-style FP is already **4.33%** on `safety-v3`. When a teen plays an T-rated anime RPG, reads a webtoon, or watches a gaming stream on Discord, a 4.3% per-frame false positive rate at 2 samples/s means **a false cover every ~12 seconds**.
   - Worse, Architect (§D.2) proposes that whenever *any* anti-cheat (EAC, BattlEye, Vanguard, FACEIT—which run in Fortnite, Apex, Valorant, League of Legends, Elden Ring, Halo, Destiny 2) is detected, the guard switches from a regional cover to an **opaque full-screen window**! One false positive on a Fortnite character skin or loading screen will instantly slap an opaque full-screen cover over the middle of an online match. That teen or adult will uninstall Toolize within 5 minutes.
3. **Covering Work Apps & Password Managers (`WDA_EXCLUDEFROMCAPTURE` & False Covers):**
   - If an adult is sharing their screen on Zoom, opening 1Password, inspecting medical/dermatology photos, or shopping for clothing, and `Toolize.Guard` covers the entire window because of display affinity or a false positive—and **refuses to let them click through or dismiss it without driving across town to get their USB key**—they cannot do their job.
4. **Laptop Battery, Heat, and Hybrid-GPU Wakeups:**
   - Even with dirty-rect gating, keeping an active `IDXGIOutputDuplication` session open at 60–144 Hz while a user watches a clean 1080p lecture or codes alongside a subtle animated cursor/clock forces continuous D3D composition and GPU/NPU wake states. If a 9-hour laptop drops to 5 hours of battery life or spins its fans in a quiet library, students and professionals will disable the service.
5. **Shameful or Alarmist Overlay Copy:**
   - Competitors like Covenant Eyes and Qustodio use red warning screens and accusatory language. If a kid triggers a block on an innocent search or a false-positive thumbnail while a parent or friend is looking at the monitor, an alarmist screen creates unearned shame.

### 2.2 What the UX Must Do to Keep People Using It (plus Answers to Round 1 Questions)

- **Calm, Neutral Visual Design ("Quiet by Default"):**
  - Never use red sirens or moralizing text. Region covers in `Toolize.Guard` should look like a **soft neutral frosted matte (`#242423` with subtle grain or DWM Acrylic + grayscale)**—indistinguishable at a glance from a lazy-loading placeholder.
- **Instant, Keyless "Peek / Dismiss False Cover (60s)" with Friction + Local Diagnostics (Answering Architect Q4):**
  - Architect asks whether revealing a false screen cover must require the physical USB key. **For the Screen Guard, requiring the physical key to clear a false cover over a native app will kill adoption**, because screen-level heuristics lack DOM context and *will* occasionally misfire on UI/games/slides.
  - **Solution:** Differentiate *Confirmed Explicit (`safety > 0.95` + NSFWJS porn/hentai)* from *Standard/Borderline Covers*. For non-obvious covers in Adult presets, provide a calm **"Wrongly covered? Hold for 5 seconds to dismiss for this window"** button that:
    1. Requires a deliberate 5-second press-and-hold (stopping effortless impulse clicking while rescuing legitimate work when the key is miles away);
    2. Records a **numeric-only false-cover event** (`scores`, `boxSize`, `appProcessHash`, `timestamp`—zero pixels, zero window titles) into the local verdict ring and increments the visible `Unlocks / Overrides` counter in the status log;
    3. Rate-limits overrides to **at most 3 per hour** (after 3 overrides in an hour, the key is required).
- **1-Click On-Device "That Was Wrong" Reporting:**
  - In both the browser popup (`Why was this blurred?`) and the Companion GUI (`Recent Screen Guard Decisions`), let the user flag any of the last 60 numeric verdicts as `"False positive"` with a category tag (`Cooking/Food`, `Face/Hands`, `Game/Anime`, `Shopping/Art`, `UI/Text`). Store this locally in `%ProgramData%\Toolize\feedback.json` (numbers + category tag only) so the user can export it if they choose or use it to tune their own preset/channel exemptions.
- **Battery-Aware Adaptive Throttling:**
  - When Windows reports **On Battery** (`GetSystemPowerStatus`) and no high-risk app (`Discord`, `Telegram`, unmanaged browser, media player) is in the foreground, drop DDA polling cleanly and rely on event hooks (`EVENT_SYSTEM_FOREGROUND`, window creation) + network blocking, waking DDA only when a monitored or media-rendering app is visible.
- **Direct Answers to Round 1 Open Questions:**
  - **Exposure Wording (Architect Q3 & Systems Q1):** Never claim "zero-frame blocking" outside managed browsers. Use this exact honest copy in the GUI and README:
    - *Managed Browsers (Chrome, Edge, Brave):* **"Pre-paint protection — images and videos are blurred before their first frame is drawn."**
    - *Desktop & Native Apps (Screen Guard):* **"Reaction shield — scans on-screen apps and covers flagged content within ~0.1 seconds (2–6 frames). Brief flashes may occur before a cover appears."**
  - **Code Signing (Architect Q1):** Keep personal builds unsigned if only used on the author's 2 machines, **but before shipping `Toolize.Guard` (a `SYSTEM`-token process calling `DuplicateOutput` and creating topmost overlays in the user session) to any external user, Authenticode signing is mandatory.** Without it, Windows Defender SmartScreen and ASR rules aggressively flag `SYSTEM`-spawned session helpers as remote-access trojans, and `UIAccess=true` (needed to sit in `ZBID_UIACCESS` above immersive popups) legally requires a trusted signature under `%ProgramFiles%`.
  - **Gender-Selective Blur (Architect Q5):** **Agree with Architect—do not build gender-selective face/body classifiers.** Off-the-shelf gender classifiers fail frequently on haircuts, lighting, children, and illustrations, creating constant flicker and bias. Offer a clean, deterministic **"Strict Modesty"** tier (`Revealing` + `Underwear/Swim`) instead.
  - **Dev Workflows (Systems Q3):** WSL2, Docker, VPNs, and local servers (`localhost`) must work out of the box for Adult presets; only lock down `wsl.exe` / VMs in the explicit **Teen Shield / Maximum Guard** preset or when toggled on in the GUI.

## 3. Self-Correction: Where Round 1 Red Team Was Wrong or Overreached

Auditing [`docs/council/round1-redteam.md`](file:///e:/GithubProjects/Toolize/docs/council/round1-redteam.md) against the exact codebase (`v0.9.x`) and the other council members' technical proofs reveals **five specific errors or overreaches** in my Round 1 report:

1. **Wrong on Bookmarklet / Page-JS Removal of the Fail-Closed Overlay (`round1-redteam.md` §A.3 N4):**
   - *What I claimed:* I claimed `<div id="toolize-protection-unavailable">` in `failclosed.ts` had no `MutationObserver` and could be removed by a user via a `javascript:document.getElementById('toolize-protection-unavailable').remove()` bookmarklet if `Enforce` was on.
   - *Code verification:* While [`extension/src/content/failclosed.ts:20-46`](file:///e:/GithubProjects/Toolize/extension/src/content/failclosed.ts#L20-L46) indeed appends `<div id="toolize-protection-unavailable">` to `document.body` without watching it in [`extension/src/content/engine.ts:19-24`](file:///e:/GithubProjects/Toolize/extension/src/content/engine.ts#L19-L24) (`OBSERVE_OPTS.attributeFilter` only watches `['src', 'srcset', 'sizes', 'poster', 'style', 'class', 'data-tz', 'data-tz-shadow']`), **a page script or bookmarklet DOES still see the host `<div id="toolize-protection-unavailable">` in the light DOM** (only its inner shadow root is `mode: 'closed'` at [`failclosed.ts:26`](file:///e:/GithubProjects/Toolize/extension/src/content/failclosed.ts#L26))! However, I missed two nuances:

## 10-Line Executive Summary

1. **Consensus Core:** All three council members agree: retain the MV3 extension for zero-frame DOM safe-reveal, move network/blocklist authority into `Toolize.Service` (loopback DNS + persistent WFP), and add a change-driven Screen Guard for native apps.
2. **Critical Code Vulnerability Found (`PipeServer.cs` / `RequestHandler.cs`):** Today, any user process can write `extension-heartbeat` directly to `\\.\pipe\toolize` to spoof a healthy browser extension; `PipeServer` must verify the caller PID is `Toolize.NativeHost.exe` spawned by a browser.
3. **Attacking the Screen Guard (`round1-architect.md`):** Architect's `16×16` (>128 unique colours) pre-gate is mathematically vulnerable to JPEG 4:2:0 blocks, skin close-ups, and 2D manga/hentai (which have ≤128 colours in 256 pixels and would skip ML entirely); replace with a `64×64` edge/entropy + skin-tone gate.
4. **Virtual Desktop Escape (`Ctrl+Win+D`):** A `SYSTEM`-token overlay `HWND` on Desktop 1 is invisible when a user switches to Desktop 2 (`Ctrl+Win+D`), while DDA still captures Desktop 2; overlays must track/pin across virtual desktops and verify uncloaked state.
5. **Network & DoH Escape Counter:** Adapter DNS settings race on USB tethering/WSL2; pair `DnsOverHttpsMode="off"` with persistent WFP rules blocking non-loopback port 53/853 for all processes except `Toolize.Service.exe` plus known public DoH resolver IPs.
6. **Preventing MV3 Rule Quota Crashes:** Once `Toolize.Service` runs the 487k-domain loopback DNS filter, stop stuffing daily OISD diffs into Chrome's MV3 `updateDynamicRules` (keep dynamic rules for `learnedSites` and SafeSearch only).
7. **Preventing Uninstalls from False-Positive Fatigue:** Reject default `cover-new` desktop strobing and full-screen opaque covers during anti-cheat games; pre-allowlist signed password managers/Zoom (`WDA_EXCLUDEFROMCAPTURE`) so users aren't locked out of 1Password/Bitwarden.
8. **Calm UX & Keyless Safety Valve:** Provide a rate-limited (≤3/hr), 5-second press-and-hold "Dismiss false cover" for non-explicit adult covers, paired with 1-click numeric-only on-device false-positive reporting and battery-aware idle throttling.
9. **Round 1 Self-Corrections:** Retracted `SafeBoot` registry persistence (recovery brick risk) and `VK_NEXT` synthetic scrolling; corrected `Enforcement.cs` paths, the 210–230s watchdog exposure window, and `failclosed.ts` shadow-DOM/grace details.
10. **Top Build Order:** (1) Pipe auth + DoH/URL policies + `failclosed` fix, (2) DLL-based watchdog, (3) Service signed blocklists, (4) Loopback DNS + WFP, (5) Shadow Screen Guard G0, (6) Tier B FIDO2 + Cooldown timer + Service DACL, (7–10) Screen Guard G1/G2, Curfew schedules, and Taxonomy v4.
